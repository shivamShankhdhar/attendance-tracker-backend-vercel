1. Navigate to the IAM console in the AWS Management Console
2. Click on Roles in the left navigation panel
3. Verify that a Lambda execution role exists in your account, or create a new one if needed:
   - Click Create role
   - Select AWS service as the trusted entity type
   - Select Lambda as the use case
   - Click Next
   - Attach the policy AWSLambdaBasicExecutionRole at minimum
   - Click Next
   - Provide a role name and click Create role
4. Return to the Lambda console at https://ap-south-1.console.aws.amazon.com/lambda/home?region=ap-south-1#/functions
5. Click Create function
6. Select Author from scratch
7. Enter a function name
8. Select a runtime
9. Under Permissions, expand Change default execution role
10. Select Use an existing role
11. Choose the Lambda execution role you verified or created in step 3
12. Click Create function
13. If the error persists, try creating the Lambda function in a different region to determine if this is a region-specific issue
14. If the error continues across regions, wait 15-30 minutes and retry as this may be a temporary service issue
15. If the problem persists after waiting, contact AWS Support through the Support Center in the AWS Console

3. Locate and select the root account user or the IAM user that is experiencing the access denied error
4. Click on the Permissions tab
5. Click on Add permissions, then select Attach policies directly
6. Create a new inline policy by clicking Create policy
7. In the policy editor, switch to the JSON tab
8. Add a policy with the specific Lambda permissions needed for the action you are trying to perform, such as:
   - For viewing Lambda functions: `lambda:ListFunctions`, `lambda:GetFunction`
   - For invoking Lambda functions: `lambda:InvokeFunction`
   - For managing Lambda functions: `lambda:CreateFunction`, `lambda:UpdateFunctionCode`, `lambda:UpdateFunctionConfiguration`, `lambda:DeleteFunction`
9. Specify the Resource element with the specific Lambda function ARN(s) you need to access instead of using `Resource: *`
10. If you need access to all Lambda functions in the us-east-1 region, use the resource pattern: `arn:aws:lambda:us-east-1:023524015934:function/*`
11. Review and create the policy
12. Attach the policy to the user
13. Wait a few moments for the permissions to propagate
14. Return to the Lambda console and retry the action
